00 / the whole system

Harbor, from task to result.

Harbor is an evaluation runner. It gives an agent a task in a sandbox, runs the task's verifier, and records what happened. This guide follows that path and shows where datasets and adapters, Rewardkit, and Harbor Index fit.

One useful distinction

A score answers whether the task's checks passed. A trial record explains whether the agent ran, what it changed, and whether grading itself succeeded. Do not treat a verifier error as a zero score.

01 / task

The unit of work

A task defines an instruction, an environment, and a verifier. It lives in a directory, so the prompt is only one part of it. Harbor tasks are meant to stand on their own, outside the runner.

What the agent sees

The instruction tells the agent what outcome to produce. The sandbox gives it files and tools. The task author can choose an environment that makes the work realistic without giving the agent the verifier's answer.

What the verifier sees

After the agent phase, tests/test.sh checks the final state. It writes /logs/verifier/reward.txt or reward.json. The verifier is part of the task contract, not a claim the agent makes about its own success.

02 / dataset & adapter

Where tasks come from

A dataset is a collection of tasks, usually representing one benchmark. You can author Harbor tasks directly. An adapter is useful when an existing benchmark has another format and needs to be converted.

Choose by scope

Use -t for a published task, -d for a published dataset, or -p for a local task or dataset path. One task is enough to inspect the full loop before running a benchmark.

03 / agent & sandbox

Who works, and where

The agent is the program that receives the instruction and uses tools. The model powers that agent. The sandbox is the isolated environment in which it works. These are separate choices.

Agent versus model

-a selects the agent integration; -m selects its model. The agent manages the session and tool calls. The model does not replace the agent's runtime behavior.

Environment versus verifier

The agent environment hosts the work. A verifier can run against that environment or in a separate verifier environment. A separate verifier is useful when grading needs its own dependencies or when later regrading should use recorded artifacts.

04 / trial & job

One attempt, then many

A trial is one agent's attempt at one task. A job collects trials. This distinction matters when you repeat a task, compare agents, or run a dataset concurrently.

05 / verifier & Rewardkit

How work becomes a score

A verifier evaluates the agent's output and writes a numeric reward. A plain test script can do this directly. Rewardkit is an optional Python package for composing programmatic criteria and judge-based checks.

One score or several?

Files directly under tests/ can combine into a main reward. Subdirectories can produce dimensions such as correctness and quality. Those dimensions do not automatically create the root reward key; add a root aggregation if Harbor should read one main score.

A zero is not an error

{ "reward": 0 } can be a valid grade. A missing reward file, malformed output, or verifier crash is a grading failure and needs separate diagnosis. Inspect the trial status and verifier logs before comparing scores.

Cost and isolation

Python criteria can be deterministic. Judge criteria need provider credentials and may incur model usage. If a check modifies the workspace, Rewardkit's isolation option can keep that mutation from affecting other criteria.

06 / results & regrade

Keep the evidence, not just the number

A job result is useful because you can inspect each trial. The score is only the summary. Logs, collected files, and an optional agent trajectory can show what the agent did and why grading succeeded or failed.

07 / other run modes

When a single instruction is not enough

Harbor also supports tasks with milestones and trials where a simulated user talks to the target agent. These are different evaluation designs.

08 / Harbor Index

Framework and benchmark are different things

Harbor is the reusable runner and task format. Harbor Index is one curated benchmark built on that ecosystem. You can use Harbor without running Index, and an adapted dataset does not become Index.

When to use which

To learn Harbor, run one existing task. To test your own workflow, write or adapt a task. Use Harbor Index when you want its benchmark and are ready to follow its submission rules.

09 / first run

A small way to start

One task gives you a complete trial to inspect. This command is from Harbor's quick start; it has not been run for this page.

Example commandlocal run
harbor run \
  -t hello-world/hello-world \
  -a codex \
  -m openai/gpt-5.6-luna
-tPublished task to run
-aAgent integration
-mModel used by that agent

You need Harbor installed, a working local sandbox such as Docker, and credentials for the chosen model. A real run may incur model charges. Read the official quick start before running it.
